# File Atelier

File Atelier 1.1.0 — компактное приложение на Python для безопасной сортировки файлов по
расширениям. Одна и та же проверенная логика доступна через CLI и понятное настольное окно в
светлом техническом стиле CodeVinci. Приложение читает правила из JSON, заранее строит полный план
и перемещает файлы только после явного подтверждения.

Проект решает одну задачу: помогает разобрать содержимое выбранного каталога без превращения в
универсальный файловый менеджер.

## Гарантии безопасности

- обычный запуск — предпросмотр без создания каталогов и перемещения файлов;
- изменения выполняются только с `--apply`;
- `--apply` и `--dry-run` взаимоисключающие;
- существующий файл назначения никогда не перезаписывается;
- конфликт имён разрешается суффиксами `_1`, `_2` и далее;
- по умолчанию проверяются только файлы непосредственно в выбранном каталоге;
- вложенные каталоги обрабатываются только с `--recursive`;
- символические ссылки пропускаются;
- корректно размещённые файлы не перемещаются повторно;
- вся конфигурация проверяется до построения и выполнения плана;
- по завершении выводятся числа запланированных, перемещённых, пропущенных и ошибочных операций.

## Требования и установка

Нужен Python 3.10 или новее. У проекта нет обязательных сторонних зависимостей.

```bash
git clone https://github.com/CodeVinci8/file-atelier.git
cd file-atelier
python -m venv .venv
```

Активируйте окружение и установите проект:

```bash
python -m pip install -e .
```

После установки доступны равнозначные точки входа:

```bash
file-atelier --help
python -m file_atelier --help
file-atelier --version
```

Графический интерфейс запускается одной из команд:

```bash
file-atelier-gui
python -m file_atelier.gui
```

CLI не импортирует и не запускает GUI, поэтому прежние сценарии продолжают работать без
изменений.

## Графический интерфейс

Окно File Atelier рассчитано на пользователя без терминала. В нём можно:

- выбрать исходный каталог и JSON-конфигурацию;
- явно включить обработку вложенных каталогов;
- построить или обновить безопасный предпросмотр;
- проверить таблицу с файлом, категорией, назначением и статусом;
- увидеть числа запланированных, пропущенных и конфликтующих файлов;
- применить план после отдельного подтверждения количества операций;
- получить итоговую сводку и текст каждой ошибки.

Кнопка применения недоступна без корректного актуального непустого плана. Изменение каталога,
конфигурации или рекурсивного режима немедленно инвалидирует прежний план. Во время построения и
выполнения повторный запуск блокируется, а курсор показывает состояние работы.

## Быстрый запуск

В репозитории есть готовый `config.json`. Следующая команда только покажет план:

```bash
file-atelier --path Downloads --config config.json
```

Явный `--dry-run` означает тот же безопасный режим и сохранён для совместимости со старыми
сценариями:

```bash
file-atelier --path Downloads --config config.json --dry-run
```

Чтобы выполнить показанные операции, добавьте `--apply`:

```bash
file-atelier --path Downloads --config config.json --apply
```

Для обработки файлов во вложенных каталогах требуется отдельный параметр:

```bash
file-atelier --path Downloads --config config.json --recursive --apply
```

Перед рекурсивным применением особенно полезно выполнить ту же команду без `--apply` и проверить
полный план.

## Конфигурация

JSON-объект сопоставляет категории непустым спискам расширений:

```json
{
  "Изображения": [".jpg", ".png"],
  "Документы": [".pdf", ".txt"],
  "Архивы": [".zip"]
}
```

Расширения нечувствительны к регистру; точку можно не указывать. Файлы с неизвестным расширением
попадают в каталог `Другое`.

File Atelier отклоняет повреждённый JSON, неверный тип корня, пустые категории и списки, пустые
расширения, одно расширение в разных категориях, абсолютные пути, компоненты `.` и `..`. Путь
назначения дополнительно проверяется относительно исходного каталога, включая уже существующие
символические ссылки. При ошибке конфигурации ни один файл не перемещается.

## Пример «до» и «после»

До запуска:

```text
Downloads/
├── archive.zip
├── notes.txt
├── photo.jpg
└── program.bin
```

После запуска с `--apply`:

```text
Downloads/
├── Архивы/
│   └── archive.zip
├── Документы/
│   └── notes.txt
├── Другое/
│   └── program.bin
└── Изображения/
    └── photo.jpg
```

Если `Документы/notes.txt` уже существует, новый файл получает имя `notes_1.txt`. Если занято и
оно, выбирается `notes_2.txt`. Проверка учитывает как существующие файлы, так и назначения других
операций в том же плане.

## Воспроизводимая демонстрация

Создайте четыре небольших файла:

```bash
python -c "from pathlib import Path; p=Path('demo'); p.mkdir(exist_ok=True); [(p/n).touch() for n in ('photo.jpg','notes.txt','archive.zip','program.bin')]"
```

Предпросмотр:

```bash
file-atelier --path demo --config config.json
```

Ожидаемая содержательная часть плана:

```text
archive.zip -> Архивы/archive.zip
notes.txt -> Документы/notes.txt
photo.jpg -> Изображения/photo.jpg
program.bin -> Другое/program.bin
Сводка: запланировано: 4; перемещено: 0; пропущено: 0; ошибки: 0.
```

В Windows разделитель каталогов в плане будет отображён как `\`.

Примените тот же план:

```bash
file-atelier --path demo --config config.json --apply
```

Итог:

```text
demo/
├── Архивы/archive.zip
├── Документы/notes.txt
├── Другое/program.bin
└── Изображения/photo.jpg
```

## Журналирование

Параметр `--verbose` включает информационные сообщения, `--log-level` задаёт уровень явно, а
`--log-file ФАЙЛ` дополнительно пишет журнал в файл. Повторная настройка журналирования в одном
процессе не создаёт дублирующихся обработчиков.

## Тесты и Ruff

Установите зависимости для разработки один раз:

```bash
python -m pip install -e ".[dev]"
```

Проверки проекта:

```bash
python -m pytest
python -m ruff check .
python -m ruff format --check .
git diff --check
```

## Сборка Windows-приложения

PyInstaller не входит в обычную установку. Для локальной onefile-сборки установите build extra и
выполните:

```bash
python -m pip install -e ".[build]"
python -m PyInstaller --noconfirm --clean --onefile --windowed --name FileAtelier --paths src --specpath build src/file_atelier/gui.py
```

Результат появится в `dist/FileAtelier.exe`. Каталоги `build/`, `dist/` и spec-файл не должны
попадать в Git. Тот же процесс доступен вручную через GitHub Actions workflow
«Сборка Windows-приложения»; при обычном push он не запускается и не создаёт Release.

`gui_state.py` вызывает это же ядро, а `desktop.py` только отображает и подтверждает действия.

## Ограничения версии 1.1

File Atelier сортирует только обычные локальные файлы по последнему расширению имени. В версии
1.1 нет фонового наблюдения, облачной синхронизации, плагинов, правил по датам, содержимому или
метаданным. GUI не является файловым менеджером и не редактирует сложные правила. Применение не
является общей транзакцией: если одна из операций завершится ошибкой,
уже выполненные операции не откатываются, а ошибка попадёт в сводку. Отдельный режим отмены не
предусмотрен; перед применением служит полный предпросмотр.
