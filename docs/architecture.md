# Архитектура File Atelier 1.1

CLI-ядро File Atelier по-прежнему разделено на три небольших модуля:

- `cli.py` разбирает аргументы, настраивает журналирование, показывает план и возвращает код
  завершения;
- `config.py` читает JSON, нормализует расширения и отклоняет небезопасные категории;
- `engine.py` сканирует каталог, строит неизменяемый план операций и отдельно выполняет его.

Графический интерфейс добавлен тонким слоем:

- `gui_state.py` хранит выбранные параметры, инвалидирует устаревший план и вызывает функции
  общего ядра;
- `desktop.py` содержит окно `tkinter`/`ttk`, таблицу, визуальные состояния и диалоги;
- `gui.py` является лёгкой точкой входа и импортирует `tkinter` только при запуске окна.

CLI-точки входа `file-atelier` и `python -m file_atelier` вызывают `file_atelier.cli.main`.
Графические точки `file-atelier-gui` и `python -m file_atelier.gui` вызывают
`file_atelier.gui.main`. Оба интерфейса используют одни и те же функции конфигурации и движка.

Поток выполнения: сначала полностью проверяется конфигурация, затем собираются обычные файлы без
перехода по символическим ссылкам, после чего рассчитываются все назначения и конфликты имён.
Предпросмотр останавливается на готовом плане. В режиме `--apply` движок создаёт нужные каталоги и
для каждой операции эксклюзивно создаёт файл назначения, поэтому существующий файл не может быть
перезаписан.

PyInstaller находится только в дополнительной группе `build`. Ручной Windows workflow собирает
единый `FileAtelier.exe`; обычные установка и CI не требуют PyInstaller.

Архитектура намеренно не содержит сервера, базы данных, плагинов и правил сложнее сопоставления
расширения с категорией.
